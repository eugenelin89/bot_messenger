# Investment and Ask contracts 1.0

This directory is the canonical INV-01 wire package. It defines interfaces and offline conformance checks; it does not implement an HTTP receiver, ledger, scheduler, publisher or model service. Every fixture is disposable synthetic evidence. Never import it into retained operational state.

## Authority and precedence

`schema.json` (JSON Schema 2020-12) owns all record shapes; `catalogue.json` lists root DTOs and the 18 event variants. `openapi.json` (OpenAPI 3.1) owns methods, paths, authentication, query bounds and response types. `types.d.ts` is generated, never edited independently. This profile owns semantic constraints that JSON Schema cannot express. The linked [API](../../../docs/experiments/investment/PUBLIC_API.md), [security](../../../docs/experiments/investment/API_SECURITY_AND_DELIVERY.md), [simulation](../../../docs/experiments/investment/SIMULATION_RULES.md) and [Ask](../../../docs/experiments/investment/ASK_BOTSQUAD.md) specifications own product behavior. Fix conflicts together; do not silently select a permissive interpretation.

Portfolio and Ask have independent version definitions and namespaces, initially both `1.0`. A schema-bearing request must equal its exact supported version; all objects reject unknown fields. Adding a field/event requires a new reviewed compatibility package; no tolerant parsing or silent coercion. Root `anyOf` is a convenience for structurally overlapping DTOs; endpoints validate their **named** definition, not that generic union. Runtime configuration and scopes are trusted administrative inputs, never request-authorable grants.

Asymmetri must vendor the entire directory from an exact merged BotSquad commit, record that commit and SHA-256 of `manifest.json`, and verify each file digest. Do not fetch GitHub/main while building or serving. Port/run the same golden, negative and signature cases in the consumer and check its own HTTP/SQL implementation. Schema conformance alone is not runtime acceptance. `npm run contracts:generate` regenerates types and manifest; `contracts:check` rejects drift; `contracts:test` runs offline checks. The schema `$id` is an identifier, not a currently deployed URL.

## Representation and identity

UTF-8 JSON only: no duplicate keys (including escaped aliases), comments, trailing commas, malformed Unicode, nonfinite numbers, unsafe integer numbers or more than 16 nested levels. Bound bytes before parsing. Money/prices/ratios use decimal strings with at most six fractional places; discretionary shares are positive whole-share strings. Positive sequences are bounded 18-digit strings. No exponent notation, leading plus/zero variants, NaN or infinities. Unknown numeric values are `null` with reasons, never zero. Decimal lexical spelling is part of an immutable payload; do not rewrite `1.0` to `1` after hashing.

UTC timestamps allow whole seconds or exactly three millisecond digits. Compare parsed instants, never lexical strings; retain original immutable bytes for hashing. Validate dates and finite elapsed windows. Source publication/event/availability/retrieval times have different meanings; unknown original times stay null. Public-source URLs are HTTPS without credentials, query, fragment or control characters. They are evidence links, never receiver fetch instructions.

IDs match the schema's bounded URL-safe alphabet. Future trusted producers generate collision-resistant opaque IDs (at least 128 random bits); fixture IDs are intentionally readable. All investment record/source/journal identities are scoped to experiment/run. `approvalRecordId`, `sourceOperationId`, public worker IDs and origin references are **public projections**, not raw HQ database, provider-thread, session, filesystem or grant identifiers. Private provenance mapping remains at HQ. Names and prose confer no authority. Ask session IDs are lookup keys, not authentication secrets.

## Hashes and signed transport

Use SHA-256 lowercase hex for object/content digests. RFC 8785 JSON Canonicalization Scheme (JCS), not a hand-written key sorter, defines canonical bytes. Do not Unicode-normalize input. Reject lossy JavaScript values before canonicalizing. Recipes:

- `configurationHash = SHA256(JCS(RunConfiguration))`.
- `proposalHash = SHA256(JCS(DecisionProposal))`; reviewer binds that exact revision/hash.
- `journalHash = SHA256(JCS(LedgerTransaction excluding journalHash))`; includes predecessor hash, configuration, entries and evidence.
- Event digest hashes the complete immutable `Event`, excluding receiver-added fields because they are outside that object.
- `questionHash` hashes the complete `AskQuestion` excluding `questionHash`.
- `answerDigest` hashes the immutable `AskAnswer`, **not** its delivery wrapper.
- Batch/body/content digests hash exact transmitted bytes, without JCS. Whitespace changes the body digest even when semantic event hashes match.

Use HTTPS, RFC 9421 Ed25519 signatures and RFC 9530 SHA-256 Content-Digest. This deliberately narrow profile accepts one `sig1` signature, canonical Structured Field serialization and exact component order; it is not a general RFC parser. Rejection of alternative valid RFC serializations is intentional profile restriction.

All signed requests cover `"@method" "@authority" "@path" "botsquad-generation"`. Writes additionally cover `"content-type" "content-digest" "idempotency-key"` in that order. GET has no body or write headers. Query strings, percent/dot path encodings, repeated slashes and redirects are forbidden on signed routes. Signed content type is exactly the endpoint's allowed media type, without parameters. Body digest is `sha-256=:BASE64_SHA256:`. Duplicate headers, including differently cased duplicates, are rejected before a framework combines them. Reject ambiguous Host/forwarded host, encoded-path and request-smuggling forms at proxy/server boundaries; only configured trusted proxy authority maps to the signed external authority.

Signature parameters appear in this exact order: `created` and `expires` integer epoch seconds, quoted `keyid`, quoted nonce, `alg="ed25519"`. Nonce is 22–64 URL-safe characters generated from at least 128 random bits per HTTP attempt. `0 < expires-created <= 300`; creation may be at most 60 seconds ahead, expiry at most 60 seconds behind the receiver. Check key activation/revocation, algorithm, exact method/path scope and **current** generation before replay/receipt lookup. The signed generation is a fence, not authority to advance a generation. Rotation changes key material, not publisher/question/event identity.

Signature base follows RFC 9421 §2.5: each quoted component identifier, colon and space, then its exact canonical value; LF between lines, no trailing LF; final `"@signature-params": (...)` line. `Signature` is `sig1=:BASE64_ED25519_SIGNATURE:`. `signature-vector.json` contains exact UTF-8 body/base/header bytes, a disposable public key and detached signature; the private key was never retained. Tests verify with Node crypto and WebCrypto. This does not establish HTTP proxy interoperability; INV-02 must test raw HTTP including duplicate headers.

The future receiver must transactionally reserve `(keyId, nonce)` until `expires+60`, enforce quotas and recheck current scope/generation at commit. Do not trust process-local nonce sets in production. A rejected or ambiguous attempt does not authorize a new semantic operation: use a fresh nonce/signature on frozen body. All private/signed responses, including identical-retry and error responses, have `Cache-Control: private, no-store`. Unsupported methods return 405 with `Allow`; unhandled errors use bounded generic diagnostics without raw input.

## Public archive consistency

Authenticate/signature-check before returning an existing receipt. Publisher scope binds experiment/run, policy, event classes, content types, expiry, generation and quotas. Check the separate current HQ owner grant before transmission. `Idempotency-Key == batchId` for event batches. Receipt uniqueness is publisher/run/batch; same exact body returns the original receipt, changed bytes conflict. A new batch containing an unchanged event is duplicate acknowledgment; changed canonical event under that ID conflicts. Reject mixed-run history and cross-run references. The entire batch succeeds atomically or none does.

Unique keys include run/event, run/source sequence, run/domain ID/version, run/journal sequence, run/source operation and run/valuation sequence. A valuation sequence belongs to exactly one valuation ID; revisions belong to that ID and preserve its sequence. Latest complete snapshot is greatest valuation sequence, then its greatest valid revision; arrival time cannot replace it. Source gaps may exist for withheld nonfinancial work. Journal sequences are contiguous; a complete valuation requires its exact predecessor journal hash and available marks.

References resolve against previously accepted records or earlier entries in the batch. Stage bytes before metadata, registration before artifact version, then citations. Strict kind-specific links prevent a synthesis pointing at a transaction. Exact record reads return a safe tombstone when withdrawn/withheld; do not put withdrawn payloads into events/pages/detail responses or immutable caches. Artifact registry pages include unpublished/awaiting/withheld entries without leaking their bytes. `market.action` records ticker changes and other provider actions without inventing a journal effect; `instrument.updated` binds its referenced ticker-change action and preserves stable identity plus half-open [effectiveFrom,effectiveTo) symbol-history dates. Later valuations resolve the symbol effective at valuation time; older snapshots retain their historical symbol. Financial action effects remain explicit journal transactions, never applied twice from the action event.

Orders preserve proposal/configuration/deadline/expiry/ledger expectation across status revisions. The immutable order identity is run + decision revision + order index; one order cannot be recreated to bypass rejection. Only the latest pending revision can fill, once, using the exact reviewed proposal and eligible raw opening observation. Filled status requires a matching committed fill. An order expires within its frozen maximum opening wait; absence of a valid opening price never permits indefinite retrospective fill. HQ INV-05 must implement reservations, concentration checks, calendar/cutoff/halts, ledger-version revalidation and atomic concurrency; INV-01's oracle only checks representative consistency, not a complete trading engine.

Six-decimal postings use integer arithmetic and round-half-even. Cost basis is weighted average; a full sale releases all remaining basis. `priceRoundingResidual` and `basisRoundingResidual` are exact signed rational **micro-USD** differences, posted minus exact. `roundingAdjustment` is a separately posted amount, zero in this v1 profile. Split quantities truncate to representable micro-shares; any remainder is an exact rational entitlement in **shares**, retained pending licensed action handling. Do not silently discard it or pretend it is cash. Unsupported actions suspend affected valuation/new risk. INV-05 owns complete action/benchmark journals, correction propagation and peak/drawdown recomputation.

A content upload key is the exact SHA-256; identical bytes may be staged again under a fresh transport request ID, but upload alone grants no public access. Use bounded generated CAS paths, fsync plus atomic rename, verify hash/type/length, then commit metadata. Text/Markdown/JSON/CSV <=128 KiB; metadata <=16 KiB; normalized PNG <=4 MiB, <=2048 each dimension and <=4 million pixels. The offline PNG subset is noninterlaced RGBA8, only IHDR/IDAT/IEND and filter zero. Future trusted normalization must decode/re-encode before publication. Never inline HTML/SVG/PDF or remote images. Conservative Markdown rejects raw HTML, reference definitions, embedded images and entity-obfuscated destinations; a future renderer must also escape text and validate parsed URLs. CSV formula-leading cells are rejected; a public derivative may prefix an apostrophe before hashing. No arbitrary file reads/remote URL fetching.

Public pagination is receiver append order, default50/max100. A cursor is an opaque server-stored random token bound to endpoint, run, filters, fixed upper watermark and archive epoch, with finite expiry; clients never interpret it as an integer. On expiry/restore/filter mismatch return `CURSOR_RESET`; refetch status, snapshot and a bounded page. Never silently restart a page or download all history. Date filters are calendar dates and `from<=to`; performance resolution is daily. Cache/ETag keys include visibility epoch so withdrawal invalidates all derived responses. Protected receipts are never served from public caches.

## Private Ask admission and recovery

`/api/ask/v1` records never enter public investment events, artifacts, feeds, sitemaps or analytics. Browser session uses a random 256-bit HttpOnly/Secure/SameSite cookie (`__Host-botsquad_ask`, Path=/, no Domain); store only its secret hash, with absolute expiry. Recheck cookie, ownership and current deletion/expiry on every read/write and retry. Use same-origin credentials, no permissive CORS, and Origin/CSRF proof for mutations. Same-origin GET adapters use browser Fetch Metadata/validated same-origin context when browsers omit Origin; do not assume an Origin header always exists. Cross-session resources return indistinguishable 404. IDs/URLs are never bearer credentials. Disable raw body/session/signature logging and shared caching.

Question submission creates one immutable question ID/revision/hash from server-owned session/conversation/time/history. Browser idempotency is scoped to session + endpoint + request ID and exact body; authenticate before returning duplicates. Accept one outstanding question per session. Context is an exact published transaction/order/decision/artifact version in the specified run; unavailable/withdrawn records are rejected. Public worker preference is advisory only. Reject worker/model/tool/execution/grant/callback identity fields. Treat question prose and public evidence as untrusted data, never an investment Task, command, company-memory write or permission grant.

An opted-in eligible **actual worker** supplies the answer. Deterministic routing uses topic/record authorship, capability, public-service grant, availability, uncertainty fence and budget; optional bounded model routing cannot expand that set. Store a public routing explanation; bind answer worker to trusted worker execution and provider settlement, not a model-authored name. Maintain isolated public-service context per conversation/worker/tool-schema generation, with bounded owned history only. Handoff to another eligible worker is explicit in the UI. Never resume existing private research/Task/conversation provider threads. Keep company knowledge, peer/private lookup, repository/file/network/action tools inaccessible. General questions may use a separate bounded approved public-source broker; exact historical evidence is supplied by trusted record lookup.

The website queues; HQ pulls outbound using a distinct Ask service key/grant. Capacity-one claims are leases for **delivery**, not permission to rerun a model. Persist import by `(serviceId, questionId, revision/hash)` before acknowledging a claim, plus admission/reservation/execution/provider outcome/result. Repeated claims recover existing work. Started or outcome-unknown work stays fenced even if a lease expires. Only never-started, currently authorized work is eligible for admission. Confirmed results are redelivered, never regenerated for a lost HTTP response. Provider uncertainty must join existing worker-wide fences and requires reconciliation. No automatic clearing on restart/restore.

All HQ delivery operations bind the current signed generation and server-held claim/question scope. Claim/renew/status/control-sync request IDs each freeze their exact transport bytes; new control acknowledgments require a new request ID. Answer delivery has two distinct identities: its transport `Idempotency-Key` freezes the complete wrapper (claimId, consumerGeneration, lastControlSyncId, answer); `answerId`/`answerDigest` permanently bind the canonical answer and question. A refreshed claim/control token or new reconciled generation uses a **new transport request ID with the same answer**, after authenticated receipt lookup. Receiver enforces one canonical answer per question across wrappers; changed content conflicts. Recheck controls/ownership before any duplicate is delivered. An old accepted receipt proves historical acceptance, not current permission to display deleted content.

Control sync is independent of question claims and continues while claims/traffic are idle. Cursors bind service/generation and a consistent control-log watermark. HQ durably applies **every page**, acknowledges those controls, and requests again until it receives an empty controls array and `nextCursor=null` covering all controls through the current barrier. Only that final `syncId` is a dispatch/release freshness proof; timestamps on partial pages do not authorize work. New controls after the barrier are checked locally by the website before accepting/displaying a result. `validUntil` and configured control freshness (<=60 seconds) bound the proof. Offline `AnswerProof.controlsDrained` means the trusted adapter verified this barrier; it cannot come from a visitor/model. Never advance a cursor before durable application.

Cancellation/deletion/expiry beats a late answer and applies on both hosts, including backups/restores. Before dispatch and result release recheck original contextual input **and all trusted context actually supplied**, not merely citations the answer chose to emit. Withdrawn evidence suppresses delivery. A late answer gets a suppression receipt without recreating content. Retain minimal hashes/IDs/control tombstones for bounded dedupe; purge raw text and external-provider thread content according to the reviewed provider retention capability. Restore must apply newer deletion markers and fence old consumer generations before admission; backups older than the suppression horizon cannot resume service without a safe reconciliation/reset. Do not claim deletion from a provider that cannot prove it.

Ask limits are configuration, not granted capabilities: max2000-character/16 KiB question, max8000-character answer, eight-turn history, 5/hour and20/day/session, one outstanding, 50 global queue, 10-minute TTL, one active Ask slot, one answer execution, at most one optional router execution/two broker calls, 240-second execution deadline. Enforce independent IP/network/global limits without retaining raw IP unnecessarily, 25% recommended rolling duty ceiling, worker/global uncertainty fences, higher-priority owner/deadline work, and hard input/output/token/day caps. Daily dollars may be null **only** with paid admission disabled where monetary enforcement is unavailable. Reserve worst-case usage before starting, settle measured usage after, and stop on unknown cost; current BotSquad does not yet enforce these new limits.

Session/queue/status UI must distinguish queued, routed, answering, unavailable, rejected, expired, cancelled, failed and outcome-unknown. Show the actual answering employee, historical versus new interpretation, source age and limitations; never fabricate continuous thinking or guaranteed response time. Session lifetime, short retention, provider processing notice, abuse policy and owner activation are separate launch gates.
