# Decision 026 — Single-owner Personal Operator stabilization before further feature expansion

**Date:** 2026-10-06  
**Status:** Accepted owner priority  
**Clarifies:** [Decision 017](decision_017_single_company_first.md)'s sequencing after the
bounded Prompt 11 gate; preserves Decisions 016, 019 and all existing security boundaries.

## Context

Prompt 11 proved one bounded supervised real operating loop: exact approved GitHub
document action, receipt, independent observation, scheduled reassessment and STOP.
It proved no positive business effect or broad unattended operation. An owner timing
correction and a failed model turn with bounded recovery exposed the value of reliability
work. The owner wants BotSquad primarily as a personal tool for now. Additional platform
capabilities would add complexity before daily usability has been proven.

## Decision

Stabilize and polish one-owner BotSquad in an intentionally unnumbered **Personal Operator /
Daily Driver Phase**. There is no automatic Prompt 12. Prioritize reliability, operator
clarity, smooth daily workflows, maintenance simplicity and polish. Use actual owner
experience to choose future work. Resume capability growth only through demonstrated need
or explicit owner priority, not because a prior numbered roadmap suggested the next feature.

Multi-company, collaboration/federation, Telegram, broad CRM/email/business connectors,
accounting, autonomous spending, treasury/payment/wallet, broad App Store automation,
portfolio management and speculative native iOS delivery remain deferred. Keep their
architecture documents and future constraints. Easier private remote/mobile access is a
candidate only if real use shows SSH-tunnel friction.

## Consequences

Reliability/usability may outrank architecture expansion. The roadmap becomes driven by
evidence and unnumbered after Prompt 11, with a short list of candidates reprioritized from
use. Future capabilities remain possible. Persistent employees, broad/specific mandates,
trusted authority, exact approvals, credential isolation, self-hosted private access,
bounded execution and no idle model polling remain unchanged.

The completed pilot authorizes no further external action or disposition of its unmerged
acceptance branch. Its private receipts/history remain retained after credential retirement.
See the [roadmap](../product/ROADMAP.md#personal-operator--daily-driver-phase).
