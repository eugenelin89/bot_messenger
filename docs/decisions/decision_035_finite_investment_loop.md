# Decision 035 — Finite investment operating loop

**Date:**2026-10-10. **Status:** Accepted for reviewed source integration only; genuine employee and live operation gates remain pending.

## Decision

Bind one finite owner-approved operating envelope to the existing immutable team scope and frozen run. Exact preview/start selects one to eight future exchange sessions, research windows, per-cycle/day/run execution ceilings, daily/run input/output token and microdollar cost ceilings, and bounded deterministic retry limits. The first session includes the frozen initial benchmark opening. Preview shows the derived cycle reservation (cycle execution limit multiplied by the already-approved per-turn limits); no default operational inputs are selected. Schema19 is additive and empty. Draft revisions, including A→B→A edits, retain separate immutable plan revisions; consent makes the active envelope immutable.

`Mandates.tick/nextWake` and the existing Dispatcher own due work and deadlines. There is no second timer service, continuous collector or model polling loop. Each calendar session has research, cutoff, opening, expiry and close-mark occurrences. Expiry is the simulator's original min(opening wait, run end). Occurrence identity includes the selected plan revision and session/stage; execution generation separately fences requests and callbacks after control changes. Queue insertion and occurrence advancement share one transaction. Missed research is retained without catch-up or backdating. Source waits use finite attempts and bounded backoff; uncertain model work is never automatically replayed.

The existing single discussion can wait between finite cycles, retaining original contributions, evidence, outcomes and cumulative group limits. Earlier rounds lead to later evidence-based discussion through the same compatible investment context. The final cycle uses the existing synthesis/review/finalization path; an already-finalized public discussion cannot reopen. A loop-bound group uses investment run controls rather than ordinary group start/extend/resume/finish. No global worker role, hierarchy or private context is changed.

Every claimed turn permanently reserves its full approved input/output/cost ceiling and one cycle/day/run execution. Budget days use America/New_York; the whole-run reservation never resets or refunds. Settlement records measured token/cost integers atomically with execution completion. Missing/invalid usage is unknown, and reported excess is retained; both prevent subsequent model admission. Recovered settled executions without usage remain unknown. The mandatory bounded runtime adapter remains unavailable in the current Codex implementation, so no genuine investment model execution is enabled by this packet.

Cutoff is enforced both in ordinary group progression and scheduler progression, so callback/claim ordering cannot cancel valid locked orders or admit late decisions. Financial stages intake only already-committed verified market records, then use the trusted simulator. Per-order savepoints isolate thrown admission failures. Terminal guard rejections and independent valid fills remain durable; benchmark or other returned rejections remain journalled issues for bounded retry. A transaction/crash fault rolls back the full incomplete stage. Close valuation waits for the approved opening occurrence and emits at most one valuation; missing marks eventually produce an honestly incomplete snapshot. Prior missed/blocked opening or mark stages and incomplete valuations block new risk.

Standing financial capture uses its own savepoint because the repository's nested transaction helper does not provide an independent rollback boundary. A failed capture cannot retain partial jobs, identities, sequences or capture high-water. Capture cannot authorize fresh employee prose or artifacts; exact independent publication consent is still required. BUY and benchmark admission recheck publication health and current rights; SELL can reduce risk while publication is held. All canonical v1 limitations remain explicit and unchanged.

Investment pause atomically pauses the simulator, cancels pending orders, holds new scoped work, cancels queued requests and signals runtime abort. Filled trades, provider uncertainty and reservations remain. Resume requires current authority, reconciled uncertainty, healthy publication and eligible future work; it never revives old orders or missed cycles. Stop ends the simulator and future work, including valuation. Exact control receipts return the original result. Global model pause only holds new model dispatch and waits for cutoff or an explicit state-change event. Deterministic expiry cleanup remains possible after team/source/publication revocation; it does not require a model or new-risk permission.

The private owner page `/investment-run` exposes the exact schedule, reservations, actual/unknown usage, health, orders and receipts. Blocked runs enter Owner Attention. Device APIs gain no authority. No production schedule, credential, grant, source, receiver or official run is created.
