# Decision 055 — Correctable discussion input and owner model continuation

Status: Accepted for implementation, October 15, 2026. Live completion requires separate receipts.

The owner authorized fixing and rerunning Trade with all required allowance. After Decision054 source collection succeeded, Atlas completed a HOLD proposal and Maya committed an approving paper review. Maya then supplied an answer sentence in `submit_contribution.answers`, which accepts question IDs only. The bounded adapter interrupted the turn on that argument rejection. The provider confirmed settlement, but the execution remained failed with incomplete usage. Submission correctly refused that producing execution.

Discussion schemas now state identifier length, uniqueness and count bounds, and explain that answer prose belongs in `body`. Only a dedicated error from pure identifier-list validation, after execution/scope/call/replay checks and before mutation, permits correction. The adapter returns bounded field-specific feedback at most twice within the same turn and existing deadline/tool allowance. It rechecks current authority before feedback. A third rejection, an ordinary domain error, unknown argument, identity/scope/delivery violation, changed account, actual approval request or uncertain effect keeps the existing stop behavior. This is not a general exception handler that treats all tool failures as safe.

One separately approved model continuation acknowledges the exact retained, settled input-validation failure for admission only. It never relabels execution or usage, permits use of the failed review, or refunds a spent call. The preparation binds the independent checkpoint/control revision, original envelope, prior source continuation, exact failed reservation, local executions/usage/activity/requests/receipts and proposal/review records, source packet, group and turns, portfolio head and a future research occurrence. Schema31 creates only an empty immutable preparation table.

The independent `model_continuation` event adds eight attempts to the original seven-call renewal allocation: cumulative cap15, with the two already consumed calls still counted, leaving13 at approval. The same additive limits govern run, rolling24h, worker, cycle and day admission. Effective limits derive from that event plus matching local custody; frozen policy/envelopes, baseline, duration, account/profile, concurrency, source permissions, cutoff and expiry remain unchanged. Old binaries reject the new event. Duplicate release never adds capacity or clears a later hold.

Activation atomically records its receipt, activates the existing book/loop and selects the new research occurrence. It fetches no sources. The normal scheduler starts fresh employee opening requests, records explicit supersession of prior progression markers, and preserves prior request status/output, failed occurrence, executions and usage. Employees must create a fresh proposal/revision and complete a fresh independent review. Existing completed-only submission and publication guards are unchanged. The original failure remains visible.

Restart before/after independent approval restores only the exact eligible preparation or activated state. Generic Resume cannot bypass the activation receipt. New incomplete or unknown execution, changed retained evidence, stale start or a later owner hold still prevents admission. This bounded repair makes the authorized rerun possible; it does not promise infallible providers or perpetual unattended authority.

See [renewal and live evidence](../validation/investment/OWNER-RENEWAL-20261015.md) and [Decision054](decision_054_observed_source_continuation.md).

Repeated authority reads compare every current journal row and custody byte with a fully verified replay before reusing it. File identity, SQLite integrity and all authority-root canonical paths are still checked on each read; cache misses retain the final custody read after replay. Returned state is deeply cloned, and a transaction never installs its partially applied state as a replay cache. No clock, expiry, capacity or current hold decision is cached. This avoids repeated canonical parsing while preserving corruption and independent-write detection.
