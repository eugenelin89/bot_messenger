**BLOCKING**

1. **Approval suspension needs a trusted Task lifecycle.** [Company.finish/retry](/Users/eugenelin/Documents/ChatGPT/Bot%20Messenger/bot_messenger-prompt10/src/control/company.ts:297) currently completes ordinary Tasks after successful turns; generic retry accepts `awaiting_approval`.    Persist the protected intent, immediately deny further browser actions, then transition the Task after confirmed turn settlement. Queue exactly one approval-linked continuation only after settlement and owner approval. Generic retry must not release it. Test approval arriving before turn completion, duplicate decisions, denial, cancellation, and retry.

2. **Browser lifetime and action authority must be separate.** The browser may survive a turn, but [CodexRuntime.run](/Users/eugenelin/Documents/ChatGPT/Bot%20Messenger/bot_messenger-prompt10/src/runtime/codex.ts:196) aborts tool signals when that turn finishes. Meanwhile, [Dispatcher.drain](/Users/eugenelin/Documents/ChatGPT/Bot%20Messenger/bot_messenger-prompt10/src/control/dispatcher.ts:47) has no browser-capacity admission or browser deadline.

   Specify a durable singleton session lease, separate per-execution action authority, and deadline enforcement while awaiting approval or dispatch is paused. A retained browser must not continue forwarding background requests under the finished execution. A separate broker also needs an HQ connection/epoch contract that closes orphaned sessions. Waiting for browser capacity must not consume model turns.

3. **Browser callbacks need independent settlement and uncertainty handling.** [Company.callTool](/Users/eugenelin/Documents/ChatGPT/Bot%20Messenger/bot_messenger-prompt10/src/control/company.ts:427) uses synchronous receipt handling; dispatcher draining and completion guards currently cover research only.

   Add an asynchronous computer-operation path with durable reservations, execution-wide call-ID collision checks, shared duplicate promises, cancellation, and draining before execution release. Preserve mutation uncertainty independently of confirmed model settlement. Define its fence scope so retry, a new call ID, or a replacement session cannot replay an uncertain effect. Test early model completion and transport loss while browser callbacks remain pending.

4. **Define Task-generation ownership without repurposing conversation fields.** [The execution SQL invariant](/Users/eugenelin/Documents/ChatGPT/Bot%20Messenger/bot_messenger-prompt10/src/persistence/conversations-migration.ts:68) requires Task executions to have null `session_id` and `generation`. The packet also binds approval to the “current generation” while requiring a fresh continuation generation.

   Use a separate Task-context generation record with immutable Task/worker/execution ownership. Distinguish the intent’s originating generation from the one authorized to consume it. Preserve the original approval envelope. Extend provider-reference exclusion checks in both directions across ordinary, research, conversation, mandate, and computer contexts; changing only the new binding path is insufficient.
