# Public onboarding, documentation, and support comparison

**Scope and evidence.** Three tools a small software team might use: GitHub (code/work), Linear (issue/project planning), and Sentry (error monitoring). All facts below come from **retrieved official public pages**, not hands-on signup or testing. The static reader omits scripts and interactive content. Retrieval times are UTC on 2026-10-01; page publication/last-update times were not supplied, so content freshness beyond the live response is unknown. ## Practical lessons (recommendations, not vendor facts)

1. **Show a shortest path to first value.** Pair a role/task-based start hub (GitHub/Linear) with a concrete completion event, such as Sentry’s “first event.” For a small team product, make that milestone visible without requiring users to infer it from feature lists.
2. **Layer documentation.** Offer a compact start guide, searchable topic index, and task-specific deeper pages. Put migration/import paths near onboarding for teams replacing an existing tool.
3. **Make escalation explicit.** Separate self-service answers, peer/community help, product support, and paid/dedicated support; show where to report problems and check status. Avoid making users guess whether a support form is for sales or technical issues.
